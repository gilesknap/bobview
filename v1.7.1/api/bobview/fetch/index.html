Module fetch 

Source
Expand description

Reading displays from files or over HTTP(S).

Fetched displays are kept in memory, so going back and forward or reopening a screen doesn’t fetch it again; forget clears them for a reload. Fetching blocks, so the app builds a fetched display on a thread.

A browser cannot block, nor read files: there load only reads the cache, starting a fetch for what is missing and failing with [LOADING] until it arrives, and the app builds the display again once nothing is [pending].

Natively, files that a display served from a public address names are never fetched from a private one (loopback, a private network, link-local and the like), so a display from the web cannot make bobview reach into the network it runs on; nor does a redirect lead from a public address to a private one, or from https to http. Files are found through resolve, which keeps track of who named them. A browser applies its own rules (CORS, mixed content) instead.

Functions§

forget
Drop every cached display, so the next load fetches it again. Which files displays from public addresses named is kept: fetches already queued are still checked, and a reload does not lift the check.
load
Read and parse the display at source.
refused
Whether source was refused because a display from a public address named it, so it is not one to keep (in a layout, say) as the user’s.
resolve
The file file named by the display at base (with no display, a plain Source::parse): relative names are found next to the display. One named by a display from a public address is fetched only from a public one.
user_named
The file or URL text that the user named (on the command line, in the Open panel, or in a saved layout). The user’s own choice is fetched wherever it is, whether a display from a public address named it before or names it later.
