Crate bob 

Source
Expand description

Parser for Phoebus Display Builder .bob files, and for CS-Studio BOY .opi files, which are translated into the same form (see [opi]).

A display is kept close to the XML: each Widget holds its property elements as they were written, and typed accessors read them with the Phoebus defaults. Macros are expanded later, by whoever renders the display, because their values depend on where a widget sits.

Constants§

MAX_LOAD_BYTES
The most expanded macro text, counting what was expanded as well as what it came to, that a whole load should do, for Macros::with_budget to be given. Each expansion takes the size of its text and result, so this also bounds the lookups, and so the time, of a load.
MAX_MUX_SETS
The most sets a menu mux has, as in BOY (target0…target7); any more in a <menu_mux> are ignored.
MAX_XML_DEPTH
Deepest element nesting accepted. Everything that walks the tree (from_node, split_widgets, Drop) recurses once per level. The deepest real display nests about 8 levels; a small cap also bounds the stack used when displays are embedded in one another.

expand
Replace $(NAME) and ${NAME} using lookup. $(NAME=default) falls back to the default; unknown names are left as written, like Phoebus does. Text whose expansion would take more than [MAX_WORK] (16 KiB) of output, such as nested $(M) that each name $(M) several times, is returned unexpanded, as written, rather than truncated.
