Module svg

Parsing SVGs, and the images they embed, without trusting them.

usvg parses, and resvg renders, by recursing once per level of nesting, and once per reference followed (a pattern, marker, mask, clip path or filter image drawn from another one, a <use>, …). A stack overflow aborts the native viewer. In the browser it throws out of the wasm with nothing unwound, which leaves the image loading for ever and, after a few, crashes the tab: it is not survivable either, so these limits must keep every input well inside the stack rather than rely on a trap.

So nesting is bounded twice: the XML, with references followed, before usvg parses it, and the tree usvg builds (which <use> and embedded SVGs can make deeper than the XML) before it is rendered. usvg also converts a marker, pattern, mask, clip path or <use> again wherever it is used, so how much references make it convert is bounded too. Embedded raster images are decoded at render time, so their declared sizes are checked first.

This module only depends on usvg, roxmltree, simplecss, bob and imagesize, so a test build for the browser can include it on its own.

MAX_TREE_DEPTH
Deepest nesting of groups in a parsed SVG (counting clip paths, masks, patterns, filters and embedded SVGs) that we render. Rendering takes about 28 KiB of stack a level in the browser, so this many fit even in wasm’s default 1 MiB stack. The build gives wasm 8 MiB (see build.rs), but Chromium’s own stack limit is often reached first, so that is no reason to raise this. Real symbols nest groups a few deep.
MAX_WORK
Most elements usvg may convert for an SVG, embedded SVGs included, counting each as often as references make it convert them (see Cost). usvg caches little, so references to references multiply: a few kilobytes can ask for billions. Real SVGs need at most 2000.
MAX_XML_DEPTH
Deepest element nesting of SVG XML handed to usvg, counting each reference followed as REF_LEVELS levels and the SVGs embedded in it together. A plain chain of references may be about 20 long; usvg needed about 700 to exhaust Chromium’s stack, and real SVGs follow two or three (and score at most 44).
NOT_INHERITED 🔒
Properties holding references that are not inherited, but that an element may take from its parent by inherit.
PAINT_SERVERS 🔒
Elements that a reference uses, but whose content is never drawn, so inherits nothing: a gradient names its stops and a filter its primitives (and a filter image what it draws by its own reference).
REF_LEVELS
Levels of nesting that following one reference counts as. usvg recurses through several frames for each, more than for a nested group.
SHAPE_VERTICES 🔒
More vertices than usvg gives a rect, circle or ellipse. It converts these and lines, polylines, polygons and paths to paths, and puts markers on all of them (convert_element_impl in its converter.rs).

Its work counts each element once for each time usvg may convert it: usvg converts a marker at every vertex it marks, and a pattern, mask, clip path or filter for each element using it, so references from references multiply.
