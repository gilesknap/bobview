Crate pv 

Source
Expand description

PV access for bobview.

Widgets ask a PvManager for a Pv by name and read its latest PvState each frame. The manager owns a tokio runtime on which one task per PV talks to the backend chosen by the name’s prefix:

prefixbackend
ca://Channel Access (the default)
pva://PV Access
loc://local PVs held in this process
sim://simulated signals (sine, ramp, noise …)
=, eq://formulas over other PVs

In a browser (wasm32) there is no runtime: sim:// runs on the page’s event loop, and ca:// and pva:// PVs come over a PV Web Socket ([set_pvws]).

The origin of an absolute URL: scheme://host[:port] in lowercase, without user info or a default port, and with a websocket’s scheme as the page’s (ws as http, wss as https), so a socket and a page on one server have one origin. None for anything else, including a URL with a backslash, a control character or white space: a browser reads those otherwise (\ is / to it, so ws://evil\@server/ is a socket to evil).
