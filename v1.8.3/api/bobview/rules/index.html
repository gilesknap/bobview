bobview

Module rules 

Source
Expand description

Phoebus rules: expressions over a widget’s rule PVs that override one property.

The expression language covers what rule editors produce: pv0, pvStr0, pvInt0, pvSev0, pvLegacySev0 (BOY’s numbering), numbers, strings, true/false, comparison, arithmetic, bitwise &, |, ^, << and >>, &&/and, ||/or, !/not and parentheses.

Phoebus runs a rule as a Jython script, so a .bob rule’s operators bind as Python’s do (Lang::Python): comparisons chain (1 < pv0 < 5) and bind looser than the bitwise operators (pv0 & 4 == 4), !/not looser than comparisons (!pv0 == 1 is not (pv0 == 1)), and / and % of integers floor. BOY ran rules as JavaScript, so an .opi rule’s bind as JavaScript’s do (Lang::JavaScript), as the display was written for. In both, as in Phoebus, macros in the expressions are expanded first. As Phoebus turns a rule’s JavaScript-style logic into Python, a lone = in a .bob rule is ==.

The bitwise operators take the integer part of a double, so pv0 & 4 works although pv0 is a double. Jython raises a TypeError there instead, and the rule falls through to the property’s own value; bobview is the more lenient.
